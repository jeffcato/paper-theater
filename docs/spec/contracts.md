# Paper Theater contracts v1

`pt-contracts-v1.0.0` is implemented in [Rust](../../crates/pt-contracts/src/lib.rs) and an [explicit TypeScript mirror](../../packages/contracts/src/index.ts). The frozen diagnostic boundary and exact fixture digest are in [contracts-ready.json](../implementation/integration/contracts-ready.json). Wire keys are snake_case, samples are safe nonnegative integers, source offsets are half-open Unicode scalar indices, geometry uses +X right/+Y up/+Z toward the audience, and SHA-256 values are lowercase hex. Unknown versions/actions fail. JavaScript converts scalar offsets to UTF-16 once at its adapter boundary.

The three product crates are contracts, production and server. Production's runtime and generation modules interact only through StageExecutor/RunServices. Runtime owns SQLite, reservations, provider dispatch, candidate storage, epoch checks, committed events, library revisions and activation. Generation proposes artifacts, decisions, reviewed package candidates and expected-revision library updates. The fixed twelve-stage order is defined by `STAGES`; no generic DAG or plugin framework is introduced.

Fixture/replay modes must reject provider operations before reading credentials or reserving requests. Live mode additionally needs persisted product authorization and money/request/token/repair limits. Every helper is allowlisted and bounded; a provider transport helper receives one runtime-issued attempt identity, never independent retry authority. Known rejection and ambiguous outcomes retain actual usage/evidence. Missing quota/recovery refinements are recorded as pending boundary work, not inferred from diagnostic text.

A published package pins exact byte inventories, profiles, recipes and checker/player versions. Hash order is payload inventory → acceptance → manifest → catalog. The sorted payload inventory excludes acceptance, manifest and catalog; no record contains its own hash. `verify_package_files` checks the written bytes, safe relative paths, symlinks, inventory membership and loaded-document bindings. Diagnostic artifacts are not accepted autonomous releases. `production_blockers` retains an explicit verifier-pending failure until the complete independent acceptance implementation is integrated.

New final speech auditions the selected Flash TTS model first. Imported Lite recordings keep their original model/voice identity. Required sources are Gutenberg 55, Oz Chapter 1, and Gutenberg 36, Wells Book One Chapter I, “The Eve of the War.” Historical partial excerpts supply diagnostic reuse only. Existing source/content SHA-256 provenance is retained without inventing a Git revision.

Service boundary `pt-services-v1.1.0` adds verified `read_candidate`; see [candidate-read-ready.json](../implementation/integration/candidate-read-ready.json). Candidate reads remain local to the active execution and grant no durable identity or publication permission. The contracts package exports built ESM and declarations from `dist`; run its build before direct Node consumption.

`pt-services-v1.2.0` adds optional CandidateWrite dimensions, preserved through candidate reads and artifact commits. Existing JSON may omit the field; PNG writes supply dimensions under existing FileRef bounds. See [candidate-write-ready.json](../implementation/integration/candidate-write-ready.json) and [current recorded PR CI](../implementation/integration/pr-ci-results.json).

`pt-services-v1.4.0` adds private independent acceptance policy/proposal/report records and the authoritative required-check matrix. The verifier executes byte, binding and coverage checks; it reports all unavailable verifiers and retains `production-verifier-pending`. Caller-declared passes and serialized reports confer no execution or publication authority. See [the executable API and exact owner handoffs](../implementation/integration/acceptance-evidence.md) and [its commit-bound receipt](../implementation/integration/acceptance-evidence-ready.json). Playback and legacy service wire records remain compatible.
