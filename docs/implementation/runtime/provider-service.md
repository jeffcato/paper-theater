R17 implements the three execution-bound provider-v2 methods on runtime `Services` using R13's persistent broker. [Checks and source pins](provider-service-ready.json), [observed public-method examples](provider-service-examples.json), [brief](../integration/server-provider-service-task.md).

Successful construction exists only through `Adapter::injected` under `cfg(test)` and R13's synthetic broker. Ordinary runtime construction always supplies `provider_v2: None`; there is no production constructor, credential implementation, live transport, HTTP provider endpoint or enable flag. A valid persisted descriptor, registry, synthetic accounting and authorization rows cannot activate ordinary runtime construction. Actual provider calls, UI/browser work and Git operations remain zero. Publication and `production-verifier-pending` remain blocked.

`Services` freezes the actual `StageInput` unit and input ArtifactRefs alongside its existing run/epoch/mode binding. Fixture/replay methods return typed `OfflineDispatch` before registry, reservation, transport or credential access. An active unconfigured live service returns `ProviderV2Unavailable`; stale scope returns `Cancelled`. Old trait implementors retain their unchanged immediate unavailable defaults. No method invokes legacy provider/helper methods or substitutes another operation after failure.

| Public method | Private broker execution |
| --- | --- |
| `issue_provider_v2(proposal)` | Validate the strict public proposal and exact execution input allowlist; verify original committed run-owned ArtifactRefs and CAS bytes; derive request hash from the unchanged payload; `bind_service_proposal` selects initial/retry lineage from the immutable runtime unit grant and atomically reserves all applicable quotas. Return the exact persisted descriptor. |
| `execute_provider_v2(&issued)` | Compare actual service run/epoch/unit, reject recovery descriptors, recheck scoped original content, and call `execute_issued_provider`. Its transaction authenticates complete immutable issuance, current unit/registry/repair authority, authorization, lifetime/run budgets, windows, cancellation and exact payload before once-only dispatch. Completed results retain their exact identity; cached private raw/output bytes are reverified. |
| `recover_provider_v2(request)` | Treat the descriptor as an untrusted selector. Require a separately persisted observer grant for this actual run/epoch/unit and original attempt. Recheck original immutable issuance, recipe/context/kind and original-owned inputs. The reservation transaction rechecks observer authority and latest genuine existing-job observation, then invokes only status recovery. Return the persisted wrapper with original identity and separate query accounting. |

Provider/model selections and estimates grant no spending authority. The private legacy-shaped projection uses only runtime unit, a runtime temporary attempt field and the payload's original hash; it never calls the legacy service. Payload whitespace is preserved byte for byte. Caller run/epoch/unit, context/project/credential, attempt, logical operation, retry and repair fields remain absent from the public proposal. Strict shared validators check shape; SQLite issuance equality and runtime grants independently authenticate execution.

The private unit record gains an optional runtime-selected retry predecessor, omitted for existing grants. Existing serialized grants keep their exact representation. `authorize_retry_unit` persists that selection; the existing broker accepts only the latest known-rejection predecessor with unchanged logical content/context/repair. The caller cannot select or reset it. Creative repair identity comes from the existing runtime grant, is checked against its predecessor, and charges once across restart and transport retries. Uncertain submissions cannot be repurchased, including through another run or credential context. Wait deadlines come from persisted quota windows and genuine retry observations; diagnostic text is never parsed into timing authority.

`provider_v2_observers(run, epoch, unit, original_attempt, record)` adds an immutable query grant bound to the original issued descriptor and registry binding. `provider_v2_query_scopes(id, observer, selector, receipt)` records the full actual observer and exact selector alongside R13's existing query row. The actual query start is persisted before transport; observation and recording timestamps are captured separately. Query ID, observer, completion, original result, reserved/accounted/observed usage and timestamps commit atomically with original receipt history and accounting. SQL failure leaves the dispatch/reservation unresolved, creates no wrapper or partial original receipt, and never retries the query automatically. Unreferenced private CAS bytes confer no authority.

Cached completed wrappers must match durable query identity, original result, scope, selector, reservation, charges, observed usage and timestamps, and retain the latest genuine job observation. They return byte-identical JSON without a new query or fresh timestamps. Old query rows without complete observer/timestamp metadata fail closed; no guessed wrapper, reservation reset or automatic resubmission is introduced. Restart invalidates old service epochs; a new observer cannot relabel an old query receipt or bypass an uncertain query's identity.

Status RPC completion remains separate from job completion. A successful status RPC can leave the job, original usage and query metrics unknown. Unknown/ambiguous metrics retain reservations; observed overages remain charged. Later unknown job status cannot refund earlier original overages. Genuine known query costs can settle reservations, while even a reported zero-request/zero-money status RPC retains one request charge. Queries consume no creative repairs. Overages invalidate the active epoch; their truthful private receipts remain stored even when the public method returns cancellation.

Cancellation returns promptly and prevents stage-consumable results. Bounded submission/query workers retain late receipt/accounting work if the stage await is canceled or dropped. Original results remain bound to their original run/epoch/logical/repair/retry/attempt/request/context, with obsolete disposition when appropriate; observer metadata stays separate. Recovery grants no additional artifact access. Provider-configured services read only their frozen execution inputs, so an obsolete original output cannot become an observer artifact or candidate. Raw provider/status receipts stay outside the HTTP artifact allowlist, package inventory and catalog.
