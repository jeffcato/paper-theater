# G17: generation chapter-master capacity

The generation input envelope now distinguishes the delivery master selected by verified package metadata from all other files. Only `Stage::Package` can claim the larger allowance. It reads the bounded, hash/length-verified `fixture.json`, validates its PlaybackDocument/manifest, and requires the selected `entries.audio` to equal an exact StageInput FileRef with `audio/wav` and no image dimensions. A filename or MIME label alone cannot grant the master budget. No shared contract change is needed; the service boundary remains v1.3 compatible.

The selected delivery WAV is capped at **268,435,456 bytes (256 MiB), headers included**. Other inputs retain **32 MiB per file / 64 MiB combined**. The master has a separate 256 MiB aggregate reservation; at most one exact selected identity receives it. All reservations are checked before payload reads, independent of input order. At most 64 input references are accepted, including duplicates. Identical references (ID, FileRef and provenance) are read/charged once; conflicting paths, reused IDs or changed provenance fail before any read. The verified metadata read is the only prerequisite to classifying a package master.

Generation reuses runtime's public, stateless `validate_artifact_bytes` API for R11 WAV structure validation. It does not access runtime storage, database or transport internals. Classic RIFF/WAVE PCM16 stereo 48 kHz is required for the selected delivery master, with exact physical frame count equal to the manifest/timeline domain. RIFF/chunk lengths, bounded traversal, format/byte-rate/block alignment and a single nonempty aligned data chunk follow R11. RF64, floating-point, extensible, malformed, truncated, substituted and wrong-hash/length inputs fail. Smaller non-master acoustic WAVs retain their existing native domain and tight input limits.

The Vec-based service boundary remains bounded-file processing. Generation retains at most **320 MiB of unique raw inputs** (256 MiB master + 64 MiB other). A returned input Vec is verified in place and moved into the input map; duplicate references do not trigger another read or PCM clone. WAV inspection borrows those bytes. Package inventories, manifests and required-artifact lists clone metadata only; package processing does not rewrite or propose another copy of the master. Existing JSON candidate writes remain capped at 32 MiB and can temporarily clone their serialized buffer for service verification. Decoded metadata, allocator overhead and runtime/service-owned copies are separate; this is not a measured process-RSS guarantee or a streaming generation interface. A service that returns more bytes than declared fails verification, but the caller cannot prevent that service's prior allocation through the current Vec API.

Cancellation is checked before and after every input read and before/after candidate writes. A canceled read or write produces no PackageCandidate. Runtime alone decides whether any proposed candidate is committed. Fixture and replay use only saved/temporary bytes; provider/helper/library calls panic in the capacity services.

The temporary proof creates a real **180-second / 8,640,000-frame / 34,560,044-byte** synthetic stereo master and passes it through the actual GenerationExecutor package path in fixture and recorded-replay modes. Manifest/inventory master identities and physical duration remain exact. Large media stays in temporary directories. The synthetic replacement has no accepted narration mapping: original source words/groups are retained, reveal bounds remain null and production findings remain NeedsRepair. Existing saved recordings, raw receipts, mappings and G16 fact evidence are unchanged.

The offline acoustic stage/helper stays **32 MiB per input / 64 MiB combined / 16 MiB output**, with its exact registered helper/adapters recipe unchanged. This capacity increase does not authorize a chapter-sized acoustic dispatch. Chapter acoustic processing still needs source/audio-bound segments inside that envelope or a separately versioned recipe/envelope reviewed by runtime's owner. The unchanged Python reader additionally limits each file to 16 MiB. Generation's next design must pin full-narration/chunk hashes, source scalar spans, global sample offsets and each segment's primary/independent receipts; a fact crossing an unverified segment stays unresolved. Agent 2 must register any changed helper/adapter recipe before dispatch. No segmentation or revised recipe is implemented or claimed here. Neither approach grants a final narration-to-presentation map or resolves ambiguous facts.

Verification: **29 generation tests (8 new capacity tests), 4 candidate API tests and 17 Python tests pass**, plus identity, formatting and whitespace checks. Commands and source/implementation identities are recorded in [master-capacity-ready.json](master-capacity-ready.json). The tests first exposed the universal 32 MiB rejection, a master read before aggregate rejection and double-counted duplicate references at the exact cap. Each is corrected.

The exact 256 MiB test uses a sparse temporary WAV, streamed through the public R11 verifier with 64 KiB buffers. Generation admits its selected reference once, including duplicate references, then the read service deliberately cancels before allocating a 256 MiB Vec. A 256 MiB + 1-byte declaration is rejected before that read. Separate metadata tests admit exactly 256 MiB master + 64 MiB other inputs and reject one additional byte. These admission tests complement the actual 180-second file/package/export/replay proof; they do not claim a 256 MiB package was buffered end to end.

The generation run retains G16's four matched / three unresolved facts, all 176 words / 170 groups / six measured points, unchanged raw hashes, byte-identical fact replay and zero redispatch/provider calls. Full-chapter generation, voice/acoustic/creative review, presentation mapping and production acceptance remain pending. Agent 1 owns staging/commits/pushes in the shared workspace.
