# G23: private offline voice pilot

`GenerationExecutor / Stage::Pilot` compiles a pinned director selection into verbatim one-speaker audition requests and independent two-neighbor review requests. All plans remain diagnostic and NeedsRepair. No real provider, research, audition, TTS, listening or score call was made. Synthetic silent WAVs test container/frame and identity validation; they provide no evidence that the prose was spoken.

## Source and performer integrity

Pilot reconstructs the saved Direction stage using its original immutable StageInput, Source originals/receipt, registry, recipe, request, raw response and observation. An internal verification service captures CandidateFile bytes in memory and refuses provider/helper/journal/catalog methods; no committed ArtifactRef is manufactured. The original observer identities remain unchanged and execution is forced to Replay. The reconstructed Direction plan must equal the supplied committed plan byte for byte. This reuses G22 unchanged, including its exact source, speaker attribution and compiler hash checks. Cross-run reuse grants no issuance authority.

The context's Source, book, chapter and registry must match that verified Direction context. Only supported Direction speakers can receive requests. Mentioned/visible characters cannot acquire voices. A narration-only source keeps one narrator. The dialogue example retains Mira's one genuine quoted performance and reports missing adjacent material rather than inventing another utterance.

New performers use the runtime-configured first-audition model (the examples pin `gemini-3.8-flash-tts`) and the saved director's specific model/voice/language/accent choice from the pinned catalog. Duplicate catalog model/voice IDs are rejected. No first-match fallback or human candidate selection is introduced. The first new-voice audition has empty style; later requests retain a short baseline and separately sourced acting. Acting never enters transcript text. Citation occurrence does not prove that an emotional interpretation is correct; listening and semantic review remain unresolved.

An established registry voice points to immutable voice metadata. Pilot preserves its original model, voice, catalog/reference, language/accent and baseline. Conflicting selections produce an unresolved reuse decision and no new speech request. Compatible recordings supplied as saved observations are validated and reused, including original Lite identities. Established speech jobs never dispatch regeneration. Missing recordings/catalog/reference metadata stay unresolved; replacing a voice requires a separately authorized production revision, not this stage.

## Strict private schemas

All records below are schema version 1. Typed input/envelope records reject unknown fields. Definitions live in [pilot.rs](../../../crates/pt-production/src/generation/pilot.rs), [provider observations](../../../crates/pt-production/src/generation/pilot_provider.rs), and [audio/review envelopes](../../../crates/pt-production/src/generation/pilot_evidence.rs). [Examples](../../../fixtures/generation/pilot-v1/README.md) bind actual bytes and committed test-double identities.

| Record | Required content |
| --- | --- |
| `private/pilot-context.json` | `book_id`, `chapter_id`; `source`, `direction`, `direction_input`, `registry`, `catalog`, `selection`, `recipe` FileRefs; `first_audition_model`, `speech_provider`, `review_provider`, `review_model`, `estimate` Usage, `timeout_ms`; `observations` and `reviews` FileRef arrays. `request_payloads` defaults to an empty FileRef array. No caller run/epoch/attempt/credential/repair authority. |
| Catalog | `provenance`, `provider`, `models[{id,voices[{id,language,accent,reference:ArtifactRef|null}]}]`. The file itself is the pinned source catalog. |
| Director selection | `provenance`, source/direction/catalog/registry SHA-256s; `performers[{speaker,model,voice_id,language,accent,baseline,passages}]`. A passage has `turn_id`, scalar `span`, exact `text`, separate `acting`, optional `acting_support:{span,quote}`. |
| Established voice | `book_id`, `canonical_id`, `provider`, `model`, `voice_id`, `catalog` ArtifactRef, `language`, `accent`, `baseline`, `reference` audio ArtifactRef, `recordings` observation FileRefs. Runtime owns its authoritative registry provenance; metadata alone grants no approval. |
| Take request | Exact source/direction/registry/catalog/recipe identities, speaker/canonical identity, optional established binding, model/voice/language/accent, baseline, passage, verbatim `text`, compiled `style`, no approval. One performer per request. |
| Observation | `provenance`, original `request` ArtifactRef, optional original `response` ArtifactRef, optional unchanged `issued` ProviderOperationV2 and `result` ProviderResultV2, original `findings`. |
| Saved take response | `provenance`, request/recipe/source/direction/catalog SHA-256s, speaker/model/voice, exact passage, `audio` ArtifactRef, `format:{sample_rate,channels,bits_per_sample,frames}`. Declared passage coverage is checked against the request; audible speech fidelity remains Missing. |
| Review request | Both exact take/request/raw/audio/observation identities, source context and expected source turns/handovers, baseline/acting, actual reference audio when available, explicit criteria. Assembled audio, join recipe and music context remain null until independently supplied by later work. |
| Saved review response | `provenance`, request/recipe SHA-256s, `speaker`, ordered exact audio `targets`, exact `reference_audio`, `criteria[{id,outcome,message}]`. One-sided or stale targets fail. Original Fail/Uncertain/Missing outcomes are retained; claimed Pass remains Uncertain. |

Passages retain source-turn/sentence boundaries and exact Unicode scalar spans, with no dropped words, invented dialogue or mid-word cuts. Missing adjacency is explicit. The proposal is a small audition subset, not a rewritten or shortened chapter: full original prose remains in the plan and complete production coverage stays required. No measured joins, acoustic anchors or reveal eligibility are invented.

Input bounds are 64 references/64 MiB aggregate; raw/clean source 16 MiB each; `.wav` audio with matching MIME at most 8 MiB; all other files, requests, responses and candidate JSON at most 1 MiB. Metadata cannot gain a larger limit by changing its MIME. Catalogs have at most 32 models/128 voices per model, selections 32 performers/four passages each, and observation/review plus payload inventories are separately bounded to 32. Existing acoustic/helper recipes and chapter-master limits are unchanged.

## Runtime commits, results and replay

1. Runtime freezes verified Source/Direction inputs, original Direction StageInput and plan, book registry, exact voice catalog, director selection and pilot recipe. It supplies genuine ArtifactRefs. Selection examples are explicitly synthetic; real autonomous director selection/catalog acquisition remains owner work.
2. Generation proposes `private/pilot/requests/*.json`, a cast/reuse plan and `private/pilot-handoff.json`. Runtime verifies and commits each desired request. It then adds the exact FileRef to context `request_payloads` and supplies the genuine input ArtifactRef. A CandidateFile is never converted into an ArtifactRef in production code.
3. Generation can now produce shared `ProviderProposalV2` of kind Speech or Review. Only Live mode can invoke the runtime v2 seam; this increment tests injected doubles only. Default unavailable/denied support yields `pilot-provider-v2-unavailable` and NeedsRepair. Fixture/Replay never issue, execute, recover, call legacy providers/helpers or query libraries.
4. Runtime persists original issuance/result/raw/audio bytes and usage independently of generation success. Generation validates the exact proposal/observer/issuance/result/raw/output identities; verifies actual PCM16 WAV structure/rate/channels/frame count; and proposes a private observation derivative. Ambiguous, obsolete, incomplete or unavailable issued attempts stay recorded and cannot be repurchased through generation. No envelope JSON grants execution authority.
5. Once both actual takes are available, generation proposes a separate independent review request binding the complete pair/reference/context. Runtime commits/registers it as another phase. Actual transport envelope decoding remains owner work: current take/review JSON is a direct private saved/fake format, not a claim that a vendor returns this envelope.
6. Recorded replay preserves the exact phase: keep `request_payloads` unchanged and supply committed original observations/raw/audio plus optional recorded candidates. Merely recording a proposed review request does not register new work. Compiler outputs, requests, proposals, review requests, plan and cache key are byte-identical; fresh observation derivatives become immutable replay inputs instead of being rewritten. Original issued scopes/charges remain unchanged. Cross-epoch issued records require an independently audited runtime mapping and otherwise fail validation.

Changes to source/turns, Direction, registry/binding, catalog, selected voice/model/baseline/acting, recipe, request, raw response or audio invalidate affected proposals and review targets. Actual format and frame declarations must match physical PCM. Compiler implementation hashes are bound separately from the runtime recipe. A gap/edit/mix change must receive a new exact downstream recipe and review; this increment performs no audio edit or assembly.

All plan/request/catalog/context/observation/review records stay private, including when aliased as a public image. StageOutput has no package, library mutation, journal proposal, account/catalog effect, acceptance or bulk-speech permission. Reuse decisions are proposals only. Runtime alone owns durable library bindings.

## Evidence and remaining gates

The first red test requested a Pilot plan that adapter-pending could not produce. Subsequent red cases exposed missing v2-unavailable findings, unguarded word cuts, ambiguous catalog IDs, replay accidentally advancing the review phase, review failures not reaching findings, nonempty first-audition style and forged metadata MIME limits. [Readiness](pilot-ready.json) records exact green commands, identities and test counts; [runtime handoff](pilot-runtime-request.json) records the concrete next boundary.

Real catalog/director provenance, initial reference research, real auditions and reference listening, multiple-take identity/continuity/intelligibility/fidelity/room tone, safe measured joins, actual music-context review and full speech/acoustic/presentation production remain pending. Every result remains NeedsRepair. No format test, synthetic clip, prior successful probe or claimed review pass closes those gates.
