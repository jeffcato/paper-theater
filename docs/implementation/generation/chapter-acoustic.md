# G19: bounded chapter acoustic bundles

The offline producer/verifier and the recorded-unit `Stage::Acoustic` adapter are implemented in generation-owned paths. The [small metadata example](../../../fixtures/generation/chapter-acoustic-v1/chapter-index.json) splits the saved narration into three chunks; media remains temporary or in its original fixture. Original source, request/response/receipt/recipe identities and all 176 words / 170 groups / six measured points are retained. The three unresolved facts and NeedsRepair remain explicit. No provider call, credential access, publication or Git mutation occurs.

`tools/generation/chapter_acoustic.py produce` accepts a canonical 44-byte-header PCM16 mono narration at its native 8–192 kHz rate, UTF-8 source and the existing G18 input index. This first adapter preserves the complete saved G16 evidence scope; arbitrary new chapter transcripts require a later evidence importer. A temporary larger narration can embed that scope at an explicit integer frame offset, but its unobserved remainder does not acquire independent evidence. Noncanonical/RF64/extensible/stereo sources fail explicitly. The full input is capped at 256 MiB and read/hash-copied in 64 KiB blocks; it is never passed as a helper input or loaded into a chapter-sized Vec.

The producer writes immutable original context files, `chapter-index.json`, canonical `chunks/*.wav`, `units/*.json`, derived helper `records/*.json` and `bundle-verification.json` into a new output directory. Existing output is refused. The complete source hash, Unicode scalar origin/spans, native format, full WAV/header/PCM identities, ordered half-open global frame spans and each chunk's exact WAV/PCM hashes are bound. A source unit crossing a cut keeps its original source span and is marked partial in each affected context; its prose is not invented or split into a supposedly independent observation. Chunk frame ranges partition all source PCM without duplication or omission.

The actual Python file cap is **16,777,216 bytes**, including the 44-byte header. Let `C` be all accompanying context FileRef bytes. The maximum frames per base segment are:

```
floor(min(16 MiB - 44, 64 MiB - C - 4 MiB - 44) / 2)
```

The 4 MiB reserve covers one-MiB index/unit metadata and one-MiB recorded-helper/prior-validation slots. Actual metadata, selected neighbors, byte aggregates and input counts are rechecked. Each unit has at most 64 references including replay slots, no file above 16 MiB, at most 64 MiB unique inputs and a one-MiB helper output. With the saved context (`C = 6260710`), the safe ceiling is **8,388,586 frames**, exactly a 16 MiB WAV. This is a byte envelope for offline verification, not a provider-approved transcription batch duration.

Facts retain their full global primary/independent observations and original receipt bytes. Independent receipts without an original harness recipe retain null. No new chunk receipt or chunk-local uniqueness claim is fabricated. A unit includes neighboring chunks required by each touched passing fact when the complete dependency set fits its envelope. Otherwise that cross-cut fact has a null bound and `cross_cut_evidence_missing`. Every source receipt remains bound to its original audio, not the new slice. Word/group originals are unchanged; local clipped observations are labeled partial, and their integer global samples equal original samples plus the declared evidence offset. For partial observations, `local_samples + chunk_start` names the clipped observed window; `global_samples` retains the full original measurement. A point on a cut belongs to the following chunk.

`verify_bundle` reconstructs the complete original WAV hash from its canonical header and every verified chunk PCM payload. It checks ordered complete coverage, source contexts, saved helper records, original scope placement and all declared identities. `verify_unit` only reads its exact bounded allowlist. The Rust adapter independently reruns G16 normalization/fact verification against the full source/transcript context, verifies source/receipt/chunk identities and all integer offsets, and compares the saved helper record with its own reconstructed observations. All required chunk bytes must be present before a cross-cut fact receives a bound. Adverse recorded findings survive; missing helper registration never discards G16 uncertainty.

The saved three-chunk example keeps four matched facts and three unresolved. The cellar fact needs chunks 0000 and 0001 and retains its conservative global bound 546720; removing chunk 0001 makes that derived bound null. The native-clock 0.75-second rule is unchanged. G18's verified delivery-domain bounds and its original media/map remain unchanged; no new delivery map is fabricated for a larger narration.

The temporary chapter proof uses **600 seconds / 14,400,000 frames / 28,800,044 bytes**, above the Python single-file cap. It places the original narration at frame 1000000 and produces two bounded chunks, the first exactly 16 MiB. Full PCM reconstruction succeeds and the maximum-sized unit passes through RunServices/StageExecutor. All four original matched facts remain visible as scoped imports, while their new chapter-wide bounds remain null because the rest of the chapter has no global independent observation. No large media is committed.

Producer buffering holds bounded context plus a 64 KiB copy buffer. Verification holds bounded context and one chunk; the producer can retain its context while invoking the verifier, so raw buffers can approach twice the admitted context/unit budget (under 128 MiB), plus JSON objects, reports and allocator overhead. Rust retains at most 64 MiB unique input Vec bytes and borrows PCM; report bodies are capped at one MiB before the existing candidate writer. These are bounded raw buffers, not measured RSS or a streaming service API. Runtime must retain its CPU/time/address-space/file-output limits when registering the new helper.

The registered legacy `helper.py + adapters.py` recipe and its 32 MiB input / 64 MiB aggregate / 16 MiB output runtime envelope are unchanged. The separate new two-file helper needs the exact [registration handoff](chapter-acoustic-registration.json). Until Agent 2 registers it and owns bounded unit scheduling/import/cancellation/restart, generation only validates saved offline records; it never calls an unregistered helper. A serialized index/verification report conveys no spending, publication or executable authority. Whole-chapter runtime orchestration, general chapter transcript import, provider pilots, production reviews and acceptance remain pending. G20's shared required-check adoption is separate; the existing REQUIRED_CHECKS literal is retained.
