# G22: private source-backed Direction proposals

`GenerationExecutor` now handles Stage::Direction from verified Source-stage artifacts, a pinned book/chapter/recipe context and a frozen book registry. It compiles saved responses and exercises provider-v2 through injected doubles. All results remain diagnostic and NeedsRepair; no actual research, model transport, TTS, images, score, UI or publication is performed.

## Inputs and source integrity

Supply `private/direction-context.json` with schema version 1, `book_id`, `chapter_id`, Source-stage receipt `source` FileRef, `registry` FileRef, `recipe` FileRef, runtime-selected `provider`/`model`, planned `Usage estimate` and `timeout_ms`. These are content and identities, not issuance authority. Unknown context fields are rejected; run/epoch/attempt/credential/repair fields cannot be supplied through this format.

Direction re-runs the existing Source validator over `raw-source.txt`, `clean-source.txt`, `frozen-source.json`, compares the resulting selection with the Source receipt and verifies its original committed ArtifactRefs against the supplied inputs. Source text, punctuation, Unicode scalar mapping and actual selected book identity must match. The chapter label is explicitly runtime-pinned; selection metadata remains in the immutable Source receipt. No chapter or global offset is guessed from a model label.

The registry is private schema-1 JSON: book ID, revision and entities containing stable ID, name, aliases and optional existing sprite/voice ArtifactRefs. Its book/revision must match context and StageInput.library_revision; conflicting aliases/IDs fail closed. Existing bindings are retained as registry records, never newly approved or silently replaced. Direction does not certify their media/review bytes or allocate canonical bindings. New entities remain unresolved. Runtime must construct this snapshot from its authoritative book registry before the request; recorded replay uses the pinned snapshot without live catalog queries.

Raw/clean source inputs are at most 16 MiB each; other Direction metadata, request, response and each candidate are at most 1 MiB. The complete input envelope is at most 64 references/64 MiB. Bounds are checked before service reads, including metadata with a forged MIME label. Top-level plan inventories are bounded to 1,024 items; the metadata/output byte limits also apply to nested records.

## Private request and response

The request contains the complete selected prose and file-local `[0,N]` Unicode scalar scope, source receipt/hash, exact registry snapshot, recipe identity, book/chapter and constraints. It embeds the full private [response JSON schema](../../../fixtures/generation/direction-v1/response-schema.json). The model receives no execution/credential/repair authority. Provider/model and quota authorization remain runtime registry decisions. Positive examples use synthetic provider/model labels, not a real Muse execution.

The response proposes cast, verbatim speech turns, ordered beats, scenes/pictures, required facts/actions, reference requirements and unresolved questions. Citations contain an exact half-open scalar span and quote. `request_sha256` is an optional collector echo: a model cannot compute a self-referential request hash. The actual exact request/response relationship is checked through the committed observation and, where present, provider-v2 records.

Every model structure rejects unknown fields. Source, recipe, model, response bytes or request identity drift rejects the result before candidate writes. Invalid coverage or unsupported claims produce private typed findings and retain the proposal for diagnosis. No quote fence removal, punctuation rewriting, missing prose repair or invented source is performed.

## Compilation scope

- Cast requires actual source mentions; the narrator is a separate functional role. Whole-token name matching prevents a partial name from inventing a character. Existing canonical names/aliases cannot be rebound to another entity.
- Speaking roles require verbatim source text. Character dialogue must occupy a supported complete double-quoted span and have a citation containing that performance with adjacent explicit named attribution. Pronouns, unsupported/nested/unclosed quotation grammar and uncertain attribution require review. Mentioned or visible characters do not automatically receive speaking roles or voices.
- The existing `dramatic-script::ScriptTurn` validator supplies bounded script syntax checks. Its output is an unapproved candidate; original source text remains separate and unchanged when syntax/attribution is unsupported. Source scene/turn/beat order is never sorted into apparent completeness. Missing source intervals are reported explicitly.
- Scenes partition source order; pictures and beat/subject/fact/action links are checked. Stillness/continuation and explicit omission reasons are representable. Omission stays Uncertain. There is no fixed creative scene/picture count and no inferred audio duration, transition, measured anchor or final master.
- Facts/actions retain literal citations. A literal quote proves that text occurs, not semantic entailment or enactment. Unsupported assertions, quoted actions and unsupported player actions remain unresolved; all fact semantic reviews are missing and all actions stay non-executable. Dialogue, hypothetical/conditional passages, hearsay, figurative language and rendered clarity still need independent semantic review.
- Reference requirements retain book-local type/entity/source scope and generic style-only use. Initial research is mandatory even without model questions. Every reference has research/applicability Missing, no canonical image selection and `approved_for_asset_request: false`. No unreviewed reference, image, sprite, art profile or voice binding is attached to a production job.

The compiler preserves raw response ArtifactRefs and original adverse findings. New structural checks cannot erase older Fail/Uncertain findings. Requests, plans, coverage, recipes, registry and observations remain private; StageOutput has no package candidate or library updates. An executable package test adds actual Direction candidates and an SVG alias, then proves their hashes remain outside the audience payload allowlist.

## Runtime handoff: commit before issuance

1. Commit Source output/originals, book registry and recipe, then invoke Direction with the explicit context. If the exact compiled request is not already a committed input, generation proposes `private/direction-request.json` and a content-only handoff. It cannot construct ProviderProposalV2 yet because its payload requires a committed ArtifactRef. NeedsRepair includes `direction-request-commit-pending`; this coordination state is not a purchased creative repair.
2. Runtime verifies/commits that request and supplies its genuine ArtifactRef on the next invocation. Generation requires exact compiled bytes and produces shared `ProviderProposalV2` with kind Direction, payload, verified inputs, recipe, provider/model, estimate and timeout. No CandidateFile is converted into an ArtifactRef in production generation code.
3. Fixture/replay consumes only saved observations and never calls issuance/execution/recovery/helper/provider/catalog APIs. Missing observations remain Missing. With a committed request, Live mode may call only the runtime-bound `issue_provider_v2` / `execute_provider_v2` seam. The runtime owns authorization, durable issuance, quotas, lineage, repairs and transport. Current increment invokes those methods only on injected test services. Default unavailable/denied methods return NeedsRepair without legacy/helper fallback or fabricated results.
4. Validate the returned issuance against the exact proposal and StageInput's runtime-bound run/epoch/unit observer, then validate the result against that issuance. Wrong request, model, scope, payload ArtifactRef, context or raw-response identity fails closed. Ambiguous/rejected/obsolete/retry/recovery results retain original metadata/charges and cannot become usable plans. A partially issued attempt remains recorded for runtime resolution, not generation redispatch.
5. Runtime persists original operation/result/raw receipt bytes independently of compilation success. Generation may propose a private observation derivative containing the unchanged received records and actual committed raw-response ArtifactRef. That derivative is not an execution capability. Real transport envelopes/decoders remain adapter work: this compiler accepts the documented direct direction-plan JSON, rejects unsupported envelopes, and never replaces original raw bytes with parsed text.
6. Commit the private observation and replay with the same verified inputs/original issued scope. Current-epoch foreign records are rejected, not relabeled. Runtime must provide an audited cache/replay mapping for cross-run/epoch reuse. Optional recorded candidates must match exact reconstruction before writes. Observation originals are inputs and are not rewritten. Compiled plan/request/proposal/status bytes and cache keys remain identical; the initial observation capture is excluded from the cache-key artifact list but its exact FileRef is bound by plan/status.

Outputs are private `direction-request.json`, `direction-request-handoff.json`, optional `direction-provider-proposal.json`, optional new `direction-observation.json`, optional `direction-plan.json`, and `direction-status.json`. The plan binds compiler source, request/response/observation identities, source/coverage and unresolved findings; cache keys bind the reconstructed content. A saved provider record's transport count remains unknown rather than becoming an observed zero. Original per-metric/accounted usage is retained unchanged. Replay performs zero redispatch, journal emission, accounting/catalog mutation or library updates.

No shared record change is required. Runtime owns routing/two-phase commits, immutable observation/raw artifacts, source/chapter selection and canonical-registry provenance, new-step idempotence, actual provider adapter/authorization and independent acceptance. Missing initial research, applicability, voice pilot, semantic review, stage clarity and production verification remain mandatory blockers. File-local Direction does not adopt or invent I18 source-slice acceptance records.
