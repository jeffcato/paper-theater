## Executed proof

For each required `complete-source-coverage` row, the checker:

1. Uses the bounded, hash-verified private source bytes read from the runtime-pinned Source role. It checks exact UTF-8 bytes against candidate source text, manifest/read-along source hashes and the runtime pin. No trimming, normalization, Unicode composition or punctuation replacement occurs.
2. Re-reads the actual timeline/read-along FileRefs using existing bounded exact-byte verification and checks their parsed records against the private document. The actual manifest must match the checked candidate. A caller's modified load envelope cannot substitute for the files.
3. Calls the existing `validate_read_along` against those source bytes. Its exact leading text, ordered Unicode-scalar word spans, text and following punctuation must reconstruct every character; groups preserve every word once in order. Existing timing/group checks are reused, not reimplemented. This does not decode speech or prove its accuracy.
4. Checks actual ordered scene `source_span`s form a positive, contiguous, nonoverlapping partition of the complete pinned scope. It rejects absent scenes, duplicate/invalid IDs, empty spans, gaps, overlap, repetition, reordering and out-of-scope endpoints. It never sorts invalid authored order into apparent coverage. These spans prove representation, not semantic visual storytelling; `story-coverage` remains unimplemented.
5. Binds the source scope ID/span/hash to the independently pinned private fact inventory's source metadata. It does not infer complete facts from that inventory or certify their semantic correctness. Stale/missing inputs or unrelated scope identity cannot pass.

Coordinates are half-open **Unicode scalar indices**, not UTF-8 bytes or UTF-16 code units. Playback v1 establishes file-local coordinates only. This increment executes when runtime pins `[0, source_file.chars().count()]`. The file may be an independently selected excerpt or chapter input. A proper subspan/nonzero global offset has no explicit global-to-local mapping in current records: it returns typed `missing_source_mapping` and outcome Missing. An endpoint beyond the pinned file is `source_coverage_outside_scope` and fails. Do not guess offsets or expand an excerpt into a chapter.

A positive row binds the exact source, actual read-along/timeline, scope, consumed hashes and executed checker identity. Successfully read inputs stay in the opaque verification's recheck pins. Missing bytes, changed hashes or incompatible source metadata cannot create a positive row. Reports contain hashes/IDs/spans and typed reasons; source text, private file paths, raw receipts and journals are not added. The canonical diagnostic package historically includes a source asset; its immutable bytes remain untouched. Privacy tests use a temporary derivative with that asset removed from the explicit public allowlist. The verifier writes no payload files, and the existing private-input export blocker remains active outside diagnostic mode; full export review is still unimplemented.

New typed reasons: `missing_source_mapping`, `source_coverage_gap`, `source_coverage_overlap`, `source_coverage_order`, `source_coverage_outside_scope`, `source_content_mismatch`. Existing invalid-binding, missing/changed-byte and adverse-evidence reasons remain. Failed/uncertain observations still worsen the row even when the independent structural source proof succeeds; a later pass never erases them.

## Version and compatibility

The immutable [v1 matrix](../../../packages/contracts/src/acceptance-required-v1.json) is preserved. [V2](../../../packages/contracts/src/acceptance-required-v2.json) changes only its version and the implemented flag for `complete-source-coverage`; required IDs, target classes and scope membership are unchanged: 3 diagnostic defaults, 37 excerpt and 37 chapter requirements. A diagnostic explicitly declaring/adding source coverage gets the same narrow independent check; default diagnostic scope does not imply production requirements.

Rust keeps `acceptance_check_matrix()` and `required_acceptance_checks(scope)` signatures, now returning v2. Explicit archive access uses `acceptance_check_matrix_for_version(version)` and `required_acceptance_checks_for_version(scope, version)`. TS keeps the same functions with an optional matrix-version parameter. Unknown versions fail closed. G20's frozen v1 fixture uses its explicit v1 accessor; new producer fixture/context metadata must adopt v2 in the generation lane or remain explicitly pinned to v1 until coordinated adoption. The dead-literal cleanup permission is independent of that version migration.

Report validation accepts only paired schema/matrix **1/v1** or **2/v2**, with that matrix's actual execution set. Archived v1 receipts validate only against their original expected checker and still cannot claim source-check execution. V2 reports require the current expected checker; do not relabel old receipts, mutate their bytes or reuse old checker identity files. The immutable diagnostic v1 report snapshot proves compatibility. JSON validation remains metadata consistency, never execution authentication or a publication capability.

## Exact R15/runtime and generation handoff

- Runtime: keep policy schema 1 and all nine roles. Resolve the authoritative source file/scope/span and expected hashes from immutable runtime compilation state. Pin file-local `[0,N]`; pass the matching source metadata in the independently pinned `AcceptanceFactInventory`. Select the real source purpose independently of generation labels. An excerpt pinned as the full source can prove only that file's representation; `complete-chapter` remains an independent missing verifier. If the trusted chapter source is larger than candidate text, coverage fails.
- Refresh the trusted expected checker from `acceptance_binding_checker()` (v2/source fingerprint includes the independent source implementation and both versioned matrices). Refresh the separately verified checker-identity artifact used by generation. The callable verifier signature, private roots, in-process opaque result and `recheck_inputs()` sequence are unchanged. Persist schema-2 reports privately; never redeem serialized reports or permit catalog activation.
- Generation: preserve inherited/custom/adverse requirements and private/public separation. Adopt v2 matrix/context/checker metadata through owned tests/fixtures. Keep G20's v1 shared snapshot immutable; return a separately versioned behavior fixture if changing its metadata/behavior. No new public playback record or duplicated source-coordinate conversion is requested.
- Missing mapping request: supporting a chapter-global span with a sliced source requires an explicit independently pinned relationship among full source identity, full source scalar span, slice bytes/hash and local-to-global offset. Playback-v1 read-along/scene spans currently provide no such record. Return that concrete contract proposal to integration; until then `missing_source_mapping` blocks the proof. Do not invent source/fact/scene coverage or alter coordinates in player/runtime.

`complete-chapter`, `complete-excerpt`, provenance, speech fidelity, semantic fact/image/audio/creative reviews, device/publication/accounting checks remain separate. Four verifiers are now implemented globally (three base checks plus source coverage); **33 required excerpt/chapter verifiers remain unimplemented**. `production-verifier-pending`, all adverse findings, live authorization and production/catalog gates remain intact.
