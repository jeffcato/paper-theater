## Why the delivery order changes

The project has a substantial diagnostic foundation: shared player, saved-audio evidence, private acceptance bindings, durable storage/replay and an exact-head backend checkpoint. R18/G24 and active R19/G25 add useful real compiler and saved-data paths. Their scoped receipts do not demonstrate an autonomous accepted release.

Publication still uses an older acceptance envelope, while shared `production_blockers` unconditionally includes `production-verifier-pending`. Therefore finishing isolated parsers or declaring more matrix entries implemented cannot by itself produce a playable accepted chapter.

I20 is the reliable published baseline: implementation `d56eb71`, receipt `2e22ffd`, 268 backend/37 Python checks and exact-head CI with 343 workspace tests. It excludes later worker/UI changes. Its selected excerpt/chapter acceptance scope has five implemented checks and 32 missing. Later v4/v5 drafts are not a basis for a production-ready verdict; count actual required targets in the selected scope, not the union of every scope's registry entries.

The new unit of progress is a **runnable source → actual decisions/media → reviewed package → audience playback slice**. A new receipt is useful when it proves a missing part of that path. Test counts, planned requests and synthetic media do not substitute for it.

## Working cadence that saves time

- Two integration checkpoints each day, with a short running-demo capture. Each worker reports only: implemented behavior, exact paths/contract, relevant failing-then-passing evidence, remaining blocker and next usable handoff.
- Preserve contract-first TDD for new behavior. Run affected checks during development; run the broad aggregate on a frozen integration candidate, not every lane's unchanged full browser matrix after every edit. Schedule heavy Rust/browser checks so the shared Mac is not simultaneously overloaded. Keep production timeouts unchanged and document test concurrency.
- Keep original receipts/archives immutable. Prefer an existing commit/source inventory and one concise result receipt over another redundant snapshot/document series. Maintain one TODO/plan/blocker board; do not build project-management infrastructure.
- Integration alone stages explicit reviewed paths and pushes. Use its isolated verification checkout to avoid sweeping moving UI/worker edits. No broad staging/reset or root install over another lane's active dependencies.
- After two failed approaches or 45 minutes on a boundary, return the minimal reproducer and exact owner request. Continue independent code; do not spend the day polishing the blocker report.
- UI functional handoffs are due within one working day. Shared HTTP/SSE/player interfaces remain stable unless a reproduced end-to-end failure requires a coordinated change. Preserve the separate Studio redesign ownership override.
- No silent scope cuts or fabricated success to satisfy the calendar. Missing/uncertain evidence blocks production; a failed gate is visible immediately so time can be reassigned.
